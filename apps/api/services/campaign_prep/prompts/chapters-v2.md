# One chapter with its full original evidence — v2.3
Input: requested_chapter (ONE chapter), compact campaign dossier, all_chapter_briefs, shared_entities, shared_truths including future reveals, accepted_dependencies, full relevant source_evidence with physical page numbers, optional original page images, verified_creatures index plus relevant_source_profiles, original AI request and preferences. Output: Bundles containing EXACTLY ONE chapter whose chapter_id matches requested_chapter.id.

Author goals, events, NPCs/motives/knowledge, clues, places, secrets, timing and encounters together in this single call. Reuse shared IDs; new_entities/new_secrets are additions only, not duplicate shared entries. Prefix local IDs with the chapter ID. Keep new identities consistent with the future chapter briefs and accepted dependency commitments. Every goal references useful events and every event its goals. next_event_ids connect within this bundle. Distinct events represent meaningful situations, not single scripted actions.

map_context identifies selected original chapter images by source_page reference, physical page and source/image hashes. Some selected images contain tables or profiles rather than maps; inspect the actual pixels. Before writing directions, doors, stairs, access, heights or room connections, check the relevant map image together with its keyed prose. Derive spatial claims from that evidence, never from OCR reading order, numeric room order or a previous summary. If the image is ambiguous, preserve that uncertainty and the source reference instead of inventing a confident route. Do not add an exhaustive route guide when the existing map and focused running notes suffice.

Set source_pages to EXACTLY the requested chapter's pages (empty for AI). Read ALL supplied original pages again, including shared appendix pages. source_notes is a DETAILED running reference, not a synopsis: preserve source-specific dialogue/characterization/humor, motives, clues, tactics, retreat triggers, exact conditional round timing, transformations, map scale/heights/connectivity/access, alternative approaches, rewards/services/XP/loot and optional endings. Cover relevant appendix procedures. Keep quantities, limits, numeric DCs and source consequences exact. A page image can correct column ownership or OCR misreadings; do not merge adjacent stat blocks. Original OCR remains separately available to the live DM, but your chapter must be useful and coherent on its own. If you deliberately adapt a fact, label original, replacement and reason so the live DM has one explicit version to follow.

source_context_pages also includes supporting pages cited by this chapter's shared identities and truths. Use these original pages for relevant appendix procedures and profiles; their provenance may cite any supplied source_context_pages. Keep source_pages as the base chapter inventory. Give events and NPCs different IDs, register each encounter actor as a canonical NPC and participant, and connect next_event_ids only to actual events. A reveal's entity_id must identify what its public_text reveals and appear among the event's participants or clues; do not use an antagonist's ID for a different transformed guard.

Events are opportunities: public_description contains only sensory facts perceived on arrival, with no hidden history, future outcome or prior hero action. trigger, timing and dm_notes retain conditional source behavior and alternate player solutions. Do not change a three-round trigger into vague 'eventually'. Do not make readily shared exposition artificially secret. visible_entity_ids contains visibly present entities with safe descriptions. Hidden discoveries use reveals with canonical entity_id, earned public_text and a private condition allowing credible approaches. Meeting an NPC does not automatically reveal all their history or later truths. Secret-bearing clues need useful earned reveal text.

Encounters retain original numbers and distinct actor IDs for genuinely different creatures/groups or forms with different statistics. When the same individual moves between encounters, reuse its stable actor ID and exactly the same authoritative profile reference in every appearance. A disguise with unchanged statistics is the same individual and profile; preserve its conditional movement rather than adding another population. For a bespoke printed profile, creature is its ORIGINAL name, source_stat_block is its COMPLETE correct profile including abilities, traits, actions and spell text/list, and source_pages cites it. The engine parses that exact module text. For a source-referenced base creature use the exact verified catalogue name and empty source_stat_block consistently. If the PDF modifies a base creature, you may form a complete modified source_stat_block only from relevant_source_profiles supplied here plus explicit source changes; document the verified base and exact changes in adaptation. Never invent missing base statistics or silently pick a different monster. No encounter is necessary when combat has no useful role.

items records retain exact original operating procedures for important usable objects (eligibility, attunement, charge reset/consumption, checks/DC escalation, failure tiers and consequences) with a canonical clue entity_id and relevant event_ids. The compiler supports object custody; advanced spell transformations/charge accounting are explicit engine limits, not magically implemented by these notes. checks records are independently executable ordinary fixed-DC skill/ability/tool checks grounded in source, with stable id, action, event_ids, engine check identifier, dc and source-consistent success/failure text. Do not turn escalating item-use checks or unimplemented spell effects into a misleading static check. Each check is a possible approach, never the only solution to a goal. Entity descriptions for items must not leak secret procedure before discovery.

For AI, create rich playable detail directly from the request and shared plan; source_pages is empty and provenance authored. Do not import a previous campaign's design. Preserve player agency and treat the later-selected hero as protagonist.
