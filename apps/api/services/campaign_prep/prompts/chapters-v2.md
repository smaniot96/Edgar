# Chapter bundle authoring — v2.0
Input: requested chapter briefs, compact campaign commitments, relevant shared registry including future secrets, chapter evidence, and verified template catalogue. Output: Bundles containing EXACTLY the requested chapter IDs.
Author useful chapter bundles in this single call: goals, event opportunities, NPC participation/motives, clues, places, secrets, chronology, optional approaches, consequences and encounters together. Use several events only when they offer distinct playable situations; no separate milestone call. Every goal references its useful events and every event references its goals. Connect next_event_ids within the bundle where natural. A first event is an approachable opening; public_description contains only sensory present information the hero could perceive at arrival. Trigger/timing and dm_notes explain what can happen and how it changes if the hero takes another path or fails. Do not narrate prior hero actions.
Reuse registry entities by ID; new_entities/new_secrets are ONLY additions, never copies of shared records. Prefix local IDs with the chapter ID to avoid accidental collisions (e.g. ch_mill_goal_rescue). New secret setup/reveal chapters may point to other spine chapters. Include actual clues and who can supply them, what each person wants and knows, where they are, and how future truths explain their behavior. Avoid tying a goal to one prescribed check or path. Chapter DM guidance should help improvise when the hero surprises you.
Encounters are reusable module quantities, not fitted to a party. Only use names from the verified creature catalogue and existing actor IDs; if the source creature is unavailable, explicitly explain the coherent supported substitution in adaptation and the DM notes. If no combat is useful, leave encounters empty. Do not invent statistics. Origins distinguish actual source pages from connective inventions.

List only entities visibly present on arrival in visible_entity_ids, with player-safe descriptions. Hidden discoveries use reveals: entity_id of a clue, concise public_text describing exactly what can be learned, and private condition explaining discovery through any credible approach. Clues revealing secret truths must have useful earned reveal text. Clue entities remain in clue_ids; reveal conditions never belong in public_text.
