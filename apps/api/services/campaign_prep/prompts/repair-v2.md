# Affected records only — v2.4
Input: concrete material findings, allowed_ids from their actual dependency closure, affected_records, continuity context, original source_evidence/images and verified creatures. Output: Patch containing only exact field_edits or complete record replacements that actually need change. All other material remains accepted.

Resolve actual internal contradictions, broken causal/clue logic, consequential premature secrets or invalid playable mechanics and their real dependencies. A coherent adventure based on the PDF may differ in details, timing, encounters, rewards and optional material. Source omissions and harmless differences alone need no repair; there is no fidelity percentage or exhaustive reproduction requirement. Preserve accepted IDs, unaffected facts and the prepared adaptation's continuity. Briefly clarify only material continuity or geography changes so one version governs play. Printed profiles must remain complete, correct and truthfully sourced; supplied verified catalogue alternatives are acceptable adaptations when consistently applied. Do not invent missing statistics or assume advanced spell/item execution exists because a procedure is written down.

map_context includes selected original images from the affected records' WHOLE chapters, even when a map is outside the record's own origin pages. Physical-page/source_page references and source/image hashes identify them. When using original geography, compare actual map pixels and keyed prose for spatial directions, room connections, access, stairs or heights. OCR order and numbered rooms do not establish geometry. A coherent adaptation may differ from the book, but the prepared descriptions and map guidance must agree on the version being played. Preserve genuine ambiguity; avoid an exhaustive route guide. These images are read-only evidence and do not enlarge allowed_ids.

For topology findings restore the intended existing event links, including escalation/finale, and source-supported conditional withdrawal/re-entry paths. Never cure an invalid edge merely by deleting the only onward route or dropping its encounter. Inspect playability_audit and retained structural progression corrections when supplied. For trigger/viewpoint contradictions, make the opening safe at the earliest valid activation or narrow the actual trigger to earned physical entry; preserve useful interior details privately. Public openings cannot reset actor custody, position or HP established by play. A required capability gap needs real executable support or an explicit supported alternative that achieves the same necessary outcome; taking a wand does not restore a transformed person. Preserve source truth and retain a material blocker when no supported correction exists rather than falsely completing the finale.

For a small prose contradiction in chapter source_notes or event dm_notes, prefer field_edits: supply its allowed record_id, field, old_text copied EXACTLY as one unique substring of the supplied accepted field, and new_text replacing only that substring. Empty new_text removes the substring. Edit the superseded instruction itself, preserving unrelated surrounding guidance; do not add another correction preface that leaves the false instruction active. If multiple copies conflict, identify each with unique surrounding text in separate non-overlapping edits. Do not also replace the same field through an event or chapter proposal. Original text remains in the durable task and repair receipt, separate from active DM guidance.

Use individual entities/secrets/goals/events patches for other local changes. chapters permits a complete Bundle replacement ONLY when that chapter's supplied kind=chapter content record ID is in allowed_ids. Preserve source page inventory, event/goal IDs and every unaffected record. Replace only affected running notes/items/checks through that bundle; unrelated contained entities/secrets/events/goals must be byte-for-byte unchanged. Do not replace an extensive reference with a short correction: use exact field_edits instead. Do not change chapter inventory or remove records. New entities may be added only when an affected repaired event references them (for example distinct creatures sharing one actor ID), via entities and that repaired event's participants. One actor identity has one exact profile.

A supplied kind=chapter content record is a private reference, not an Event. Never serialize it into events or use its content-record ID as an event/location ID. Use field_edits for its source_notes, preserving the real chapter's existing events and entities.

spine is null unless campaign_spine is in allowed_ids. Keep chapter IDs. Never patch outside the closure or invent source/mechanical verification. Fix player spoilers while retaining useful private truth. If no useful repair is possible within the closure, return empty unchanged patches so the system reports lack of progress without another paid loop. Do not regenerate the campaign for a local defect.

mechanical_profiles contains shared definitions, each with id, creature, source_stat_block and source_pages. Encounter replacements contain only actor_id, profile_id, quantity and per-appearance adaptation; never inline statistics. Reuse the existing registry by ID. Correct a shared definition once through Patch.mechanical_profiles only when its ID is in allowed_ids; actual consumers are recompiled/reviewed. A new profile is permitted only when an affected repaired event references it. Distinct actors may share a profile. Repeated appearances and disguises with unchanged statistics retain the same actor and profile IDs. Do not create a second definition to mask an inconsistent reference.
