# Incremental chapter records — v2.1

Input: requested_chapter, campaign and all chapter briefs, shared_entities and shared_truths (including future reveals), original source_evidence and optional images, owned_pages, retained_chapter, unfinished_record_fields, remaining_work, verified_creatures and preferences. Output: ChapterPart. This is one useful group of related locations/events within a chapter, not a new chapter or one call per milestone.

Read original evidence again. Author the remaining useful detail for owned_pages; other supplied pages provide context, borders, shared appendices and creature profiles. retained_chapter contains durable existing records, including fully closed provisional records from an output-limited response. Reuse their exact IDs. Do not reproduce or modify them. Add only absent records, goals, events, places, motives, clues, secrets, items and checks. Complete an unfinished record as a whole record, preserving its already supplied closed fields. If retained events refer to missing entities, define those entities. Reuse canonical shared IDs; do not create chapter-local instances of shared people. Within a multi-part chapter, goals/events may reference existing IDs; do not invent duplicate goals to satisfy a packet quota. Empty record lists are valid for reference/appendix-only work.

Keep the result useful and economical. Put each fact in its appropriate record once. source_notes contains additional running detail that records do not already retain; do not copy a full transcript or repeat every event there. Preserve exact quantities, DCs, timing, tactics, map relationships, alternatives, characterization, rewards and consequences. Keep appendix procedures that apply to this part. Distinguish deliberate adaptations and uncertain evidence. The original OCR/images remain available; your authored records still need to be coherent and playable.

Goals permit creative solutions. Public arrival descriptions contain sensory facts only. Private motives, history, hidden facts and future outcomes stay private. Each earned reveal condition must justify every fact in its public_text. Register encounter actors as canonical NPC participants. Reuse shared identities and respect future secrets. Cross-part event links must use supplied stable IDs or IDs you actually define; a later part can add further opportunities.

For a printed bespoke creature, source_stat_block retains its complete correct profile, spells and traits; source_pages cites original evidence. For a base creature use the exact verified catalogue name. Source modifications require a supplied verified base, precise documented changes and a complete resulting profile. Never fill omitted stats from memory. items retain original operating rules, eligibility, resources, DC escalation and failure consequences; checks are optional ordinary fixed-DC source checks, not unsupported spell/resource automation. Every encounter preserves original numbers; preparation is hero independent.

If recovering_output is true, compare ALL original chapter pages with retained_chapter. Finish only the missing/unfinished material; do not rewrite already complete records or their prose. Original source_pages citations do not prove a page was completely authored. Set complete=true only when the assigned source content is accounted for across retained records plus this response. source_pages must then equal owned_pages exactly. If useful work remains, set complete=false and describe concrete remaining_work so the next call can continue without repeating this work. This is continuation by records, never continuation of an unclosed JSON string.

For AI, source pages are empty; author directly from the premise and chapter brief, using authored provenance. Complete the missing playable material rather than repeating an outline. Return one complete JSON object with no padding or trailing commentary.
