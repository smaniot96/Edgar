# Incremental chapter records — v2.4

Input: requested_chapter, campaign and all chapter briefs, shared_entities and shared_truths (including future reveals), original source_evidence and optional images, owned_pages, retained_chapter, unfinished_record_fields, remaining_work, verified_creatures and preferences. Output: ChapterPart. This is one useful group of related locations/events within a chapter, not a new chapter or one call per milestone.

Read original evidence again. Author the remaining useful detail for owned_pages; other supplied pages provide context, borders, shared appendices and creature profiles. retained_chapter contains durable existing records, including fully closed provisional records from an output-limited response. Reuse their exact IDs. Do not reproduce or modify them. Add only absent records, goals, events, places, motives, clues, secrets, items and checks. Complete an unfinished record as a whole record, preserving its already supplied closed fields. If retained events refer to missing entities, define those entities. Reuse canonical shared IDs; do not create chapter-local instances of shared people. Within a multi-part chapter, goals/events may reference existing IDs; do not invent duplicate goals to satisfy a packet quota. Empty record lists are valid for reference/appendix-only work.

The prepared adventure may coherently adapt the source; exact fidelity and exhaustive detail are not acceptance requirements. Keep the accepted version's plot, identities, clues and consequences logical. Combine, omit or invent remaining details when useful, without contradicting retained records. Harmless differences need no change log; briefly establish material continuity or geography changes.

map_context retains selected original images from the WHOLE chapter, including maps outside owned_pages. Each reference supplies its physical page and source/image hashes. When using source geography, inspect actual map pixels and keyed prose for directions, room connections, doors, stairs, access or heights; OCR order and numbered rooms do not establish geometry. Coherent geography adaptations are acceptable when all prepared guidance agrees. Some selected visuals are profiles/tables, so first check what each image contains. Keep map evidence as context without claiming its page as owned work. Preserve uncertainty with its reference when a route is unclear. Focus on spatial facts needed for this part without an exhaustive route guide.

Keep the result useful and economical. Put each fact in its appropriate record once. source_notes contains additional running detail that records do not already retain; do not copy a full transcript or repeat every event there. Give quantities, timing, tactics, spatial relationships, alternatives and consequences enough specificity to run the prepared situation consistently. Include relevant procedures without reproducing every source detail. Report uncertain evidence truthfully. Original OCR/images remain available for compatible missing detail; authored records must still be coherent and playable.

Goals permit creative solutions. Public arrival descriptions contain sensory facts only. Private motives, history, hidden facts and future outcomes stay private. Each earned reveal condition must justify every fact in its public_text. Register encounter actors as canonical NPC participants. Reuse shared identities and respect future secrets. Cross-part event links must use supplied stable IDs or IDs you actually define; a later part can add further opportunities.

Write runnable module situations with clear entry/exit geography, keyed exterior/interior distinctions, NPC motives/knowledge, observable objects, encounter tactics/morale, nonviolent options, consequential failure, rewards and conditional endings. Give distinct stable place identities to navigable places that need distinct public map labels. Every event must be reachable by valid next_event_ids from the chapter entry or an earlier chapter; include branches into escalation/finale and credible withdrawal/re-entry routes. Never leave a required later encounter as an isolated inventory row. The event trigger and public_description share a viewpoint: if contact from outside can activate it, the public opening stays outside and reveals no unseen interior contents. Activation never means physical entry. Keep actor staging/custody conditional so later openings respect transfer, separation, defeat and resource state established by play.

Declare each new mechanical profile once in mechanical_profiles, before events, with stable id, creature, complete source_stat_block and source_pages. Encounters contain only actor_id, profile_id, quantity and per-appearance adaptation; never inline or repeat statistics. Reuse retained_chapter.mechanical_profiles and known_mechanical_profiles by ID, without redeclaring them. Multiple actors may share a profile; every appearance or disguise of the same individual reuses both actor_id and profile_id. If retained events reference an undeclared profile, complete that missing definition. A printed definition retains its original name, complete correct profile, spells and traits with original source_pages. A suitable supplied verified catalogue creature is an acceptable adaptation: use its exact catalogue name and empty source_stat_block. Material substitutions need only a concise adaptation note. Reuse stable actor IDs and exact authoritative profile references, including conditional movement. Source modifications require a supplied verified base, documented changes and a complete resulting profile. Never fill omitted stats from memory or claim invented mechanics are verified. items describe consistent useful operating rules; checks are optional ordinary fixed-DC checks for the prepared situation, not unsupported spell/resource automation. Encounter populations must agree within the prepared adventure; preparation is hero independent.

If recovering_output is true, inspect all supplied chapter pages alongside retained_chapter. Finish only useful missing/unfinished material; do not rewrite already complete records or their prose. Page citations alone do not prove completion, and completion does not require reproducing every original detail. Set complete=true when retained records plus this response form a coherent playable treatment of the assigned situations with their necessary causal links and references. source_pages must then equal owned_pages exactly as an evidence inventory. If useful work remains, set complete=false and describe concrete remaining_work so the next call can continue without repeating this work. This is continuation by records, never continuation of an unclosed JSON string.

For AI, source pages are empty; author directly from the premise and chapter brief, using authored provenance. Complete the missing playable material rather than repeating an outline. Return one complete JSON object with no padding or trailing commentary.
